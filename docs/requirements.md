## 一、产品定位

mairror 是一个 **AI 品牌可见性监测服务**。帮助企业看清"AI 眼中的自己"：

- AI 搜索（ChatGPT、Claude、Perplexity、Bing Copilot）里对你的品牌如何描述？
- 竞品在 AI 搜索结果中的出现率与你相比如何？
- 你的网站是否具备被 AI 引用所需的技术基础？
- 如果不理想，怎么改？

**名称含义**: mAIrror = AI 是品牌之镜。不是传统的"SEO 排名工具"，而是帮你看到 AI 搜索引擎里你的品牌镜像。

**核心差异化 vs Sivussa**:
- Sivussa: 一次性审计 PDF → 告诉你有 47 个问题 → 你自己想办法
- mairror: **持续监测 + 竞品对比 + 改造方案** → 每周告诉你排名涨跌 + 跌了给原因 + 提供改的报价

**核心理念**: 不做"AI 搜索排名"（AI 结果非确定性，"排名"概念不成立），改做"可见性"——品牌在 AI 领域的提及率、竞品对比、被引用的技术就绪度。

## 二、功能范围

### 2.1 In Scope（MVP 必做）

| 功能模块 | 说明 |
|---------|------|
| **免费检测工具（获客引擎）** | 用户输入域名，实时返回 5-8 项关键指标，作为转化漏斗入口 |
| **品牌监测（周期性）** | 针对用户设定的关键词/品牌名，周期调用多 AI 平台 API，统计品牌是否被引、被如何描述，变动时告警 |
| **竞品对比** | 同一意图域下，用户网站 vs 竞品网站的相对引用率对比，输出可见性得分和差距分析 |
| **就绪度审计** | 深度扫描网站技术层面对 AI 代理的友好程度 |
| **用户仪表盘** | 趋势图、监测数据历史、告警规则管理 |
| **邮件/通知系统** | 周报推送、排名变化告警、竞品对比报告 |
| **改造方案咨询（upsell）** | 基于审计结果，提供可执行的改造方案和实施服务 |

### 2.2 Out of Scope（明确不做）

- 传统 SEO 排名追踪（Google/Bing SERP position）—— Semrush/Ahrefs 的领域
- AI 内容生成（博客/文案撰写）
- 网站建设/托管
- 保证"出现在 AI 搜索结果中"——引用概率可提升但不可承诺
- 付费广告投放
- 全自动 PDF 报告生成（MVP 先用邮件 HTML + 在线仪表盘）

| 角色 | 权限 | 说明 |

| **Admin（内部）** | 管理用户、查看系统状态、内容管理 | 运营后台 |

## 四、用户流程

### 4.1 主流程：从免费检测到付费监测

```
用户到达 landing page
  │
  ├─ 看到免费检测入口（输入框 + CTA）
  │
  ├─ 输入域名 → 点击"照一照"
  │     │
  │     └─ 实时调用 Perplexity/OpenAI API
  │          │
  │          ├─ 成功: 展示检测结果卡片 + "每周自动监控 X 关键词 → $X/月" CTA
  │          └─ 部分失败: 已获取指标照常展示，失败项标注原因
  │
  ├─ 用户注册/登录（email + OAuth）
  ├─ 选择订阅方案 → 支付
  ├─ 设定要监测的关键词/品牌名
  │
  └─ 系统开始周期监测
       ├─ 每周: 品牌监测周报（邮件 + 站内）
       ├─ 每月: 竞品对比报告（邮件 + 站内）
       └─ 异常时: 实时告警通知
```

### 4.2 分支流程：改造方案 upsell

```
监测中发现排名/引用率下降
  │
  ├─ 系统自动推送"改造方案推荐"
  ├─ 用户点击 → 跳转咨询购买页
  ├─ 支付成功 → 人工/半自动审计 + 改造方案交付
  └─ 可选: 实施服务（更高单价）
```

### 4.3 错误与边界处理

| 场景 | 处理策略 |
|------|---------|
| API 调用超时/失败 | 单次失败不影响其他数据源，报告中标注；连续失败告警 |
| 域名无法访问 | 提示"无法访问该网站，请检查 URL" |
| 网站在 AI 搜索中完全无引用 | 明确告知"目前未检测到引用"，推荐就绪度审计服务 |
| 用户取消订阅 | 保留监测数据 30 天，可随时恢复 |
| 支付失败 | Webhook 处理，邮件提醒更新支付方式 |
| 免费用户滥用 | 单 IP/设备限制免费检测频率 |

## 五、业务规则

### 5.1 数据获取规则

1. **不报排名，报"可见性"** — AI 搜索结果非确定性，不跟踪具体排位，而是统计"在 N 种提示词变体中被引用的比例"（提及率）
2. **批量查询 + 统计分析** — 同一意图生成 20-30 个变体 prompt，统计引用次数，输出"可见性得分"
3. **多平台覆盖** — Perplexity API（首选，引用结构化）、OpenAI web search、Claude web search、Bing Web Search API
4. **品牌监测优先** — 品牌名搜索比泛关键词搜索更确定性，先做品牌监测，再做意图域监测

### 5.2 报告规则

5. 周报：每周一发送，包含品牌监测结果、引用率变化趋势
6. 月报：每月 1 号发送，包含竞品对比、可见性得分变化
7. 告警：品牌引用率下降超过阈值时实时通知
8. 免费检测：不注册也能用，但结果不保存历史

### 5.3 数据一致性

9. 同一次监测任务中，所有 AI 平台查询使用相同的 prompt 变体集合
10. 历史数据只增不删不修（append-only），确保趋势可追溯

## 六、就绪度审计维度

| 检查项 | 说明 |
|--------|------|
| **llms.txt** | 是否存在、格式是否正确、内容是否完整 |
| **robots.txt** | 是否声明 `ai-train` 等 AI 相关指令 |
| **JSON-LD 结构化数据** | Organization/WebSite/Article 等 schema 是否完整 |
| **内容协商** | 是否支持 `Accept: text/markdown` 等 AI 代理友好响应 |
| **Core Web Vitals** | LCP/FID/CLS 性能指标 |
| **内容可摘要性** | 页面内容是否适合被 AI 直接摘要 |

---

## 七、验收标准（Acceptance Criteria）

1. 用户输入任意可访问的域名，免费检测在 10 秒内返回至少 5 项指标的评分
2. 免费检测结果页有明确的 CTA 引导注册付费
3. 付费用户的品牌监测周报在每周一 9:00（用户时区）准时推送
4. 竞品对比报告包含至少 3 家竞品的数据和可视化图表
5. 当引用率连续 2 周下降超过 30% 时，用户收到告警通知
6. 就绪度审计报告覆盖 llms.txt、robots.txt、JSON-LD、Core Web Vitals、内容协商 5 个维度
7. 用户可以在仪表盘查看 90 天内的监测历史趋势图
8. 整个注册 → 订阅 → 首次监测 → 收到报告的流程可独立完成，无需人工介入

## 八、工程影响分析

### 8.1 技术栈建议

| 领域 | 技术选型 | 说明 |
|------|---------|------|
| **数据层** | PostgreSQL + Drizzle ORM | 每个客户 × 每个关键词 × 每次查询一条记录，时序查询 |
| **任务调度** | Inngest（已有）/ BullMQ | 定时触发批量监测任务，处理 API 限速和重试 |
| **多模型调用** | Vercel AI SDK / OpenAI SDK | 统一 Perplexity、OpenAI、Claude、Bing 的调用接口 |
| **前端** | Next.js 15 + Recharts/Tremor | 仪表盘 + 趋势可视化 + 免费检测工具 |
| **支付** | Creem（已有） | 订阅管理 + Webhook 触发服务开通 |
| **邮件** | Resend + React Email（已有） | 周报/月报/告警推送 |
| **存储** | Cloudflare R2 / S3（已有） | 报告存档、用户资产 |
| **部署** | 自建服务器 / Vercel | 前端 + API Routes |

### 8.2 关键工程决策

- **监测是周期性的不是实时的** — 不需要 streaming，批量调用 API 后聚合结果
- **prompt 变体管理是核心** — 需要维护一套 prompt 变体生成策略，确保统计有意义
- **API 成本控制** — 每次监测消耗多个 AI API token，需做好用量预估和成本分摊到定价
- **MVP 不需要 PDF 报告** — 先从邮件 HTML 报告 + 在线仪表盘开始

### 8.3 新增数据表（预估）

```
monitored_keyword     — 用户监测的关键词
monitoring_result     — 每次监测的原始结果（append-only）
competitor            — 用户设定的竞品列表
competitor_result     — 竞品监测结果
visibility_report     — 周报/月报记录
audit_result          — 就绪度审计结果
alert_rule            — 用户告警规则配置
```

## 十一、竞品分析摘要

### Sivussa.com (323-wolf-pages)

- **定位**: AI-native website visibility audit service（AI 原生网站可见性审计）
- **技术栈**: Preact SPA + Vite + Cloudflare Pages
- **商业模式**: 一次性审计 99 欧，无试用
- **弱点**:
  - 零社会证明（无案例、无数据、无客户 logo）
  - 付费墙太硬（无免费试用/预览）
  - AI 审计引擎源码不公开（仅营销站点开源）
  - 营销内容疑似 AI 生成，质量存疑
- **可借鉴**: llms.txt 生成、Agent Skills、内容协商、JSON-LD 等 AI 代理友好技术

### mairror 的差异化优势

| 维度 | Sivussa | mairror |
|------|---------|---------|
| 收入模式 | 一锤子买卖（99 欧一次） | 月/季订阅（ARR 驱动） |
| 客户粘性 | 低（做完就走） | 高（每天/每周看数据） |
| 转化路径 | 付费墙直接拦死 | 免费检测 → 付费监测 → 咨询 upsell |
| 价值主张 | 一次性诊断（what's wrong） | 持续监控 + 改造执行（track + fix） |
| LTV | ~99 欧 | ~99×12 = 1188 欧/年 |
| 信任建设 | 无 | 免费工具 + 公开案例 + 数据仪表盘 |

## 十二、MVP 实施路线

```
第一阶段（1-2 周）: 免费检测工具 + landing page
  ├─ 域名输入 → Perplexity API 调用 → 5-8 项指标展示
  ├─ 营销官网（基于 NextDevTpl）
  └─ 手动跑 5 个真实客户做案例

第二阶段（3-4 周）: 付费监测 + 自动化
  ├─ 用户注册/登录 + 订阅支付
  ├─ 关键词设定 + 定时监测任务
  ├─ 周报邮件（HTML）
  └─ 基础仪表盘

第三阶段（5-8 周）: 竞品对比 + 就绪度审计
  ├─ 竞品添加 + 对比报告
  ├─ 就绪度审计报告
  └─ 告警系统

第四阶段（9-12 周）: 改造方案 + 咨询服务
  ├─ 改造方案 productized service
  └─ 白标报告（渠道合作）
```
